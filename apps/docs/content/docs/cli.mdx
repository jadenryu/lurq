title: CLI reference
description: Use the same lurq engine straight from your terminal.
---

The lurq engine is usable standalone from the terminal, with the same scoring and
retrieval the MCP tools expose. Add `--json` to any command for machine-readable
output.

<Callout type="info">
  Run `lurq setup` first. The query commands read whichever index is configured:
  the hosted service via your stored API key, or your own Postgres if
  `DATABASE_URL` is set and no key is. A key wins over `DATABASE_URL`: otherwise,
  running `lurq` inside your own Postgres-backed app would point package lookups
  at that app's database. Operators holding both can force the local index with
  `LURQ_LOCAL=1`. See [Self-hosting](/docs/self-hosting).
</Callout>

## Querying the index

```bash
lurq recommend "a form library for react"
lurq recommend "debounce a function"
lurq evaluate zod
lurq compare drizzle-orm prisma typeorm
lurq verify lodahs
```

`recommend` accepts `--category` and `--min-confidence` to narrow results.

## Scoring controls

```bash
lurq weights                                  # show & explain the weight model
lurq edit-weights --set composite.lambda=0.5  # override a weight (or --reset)
```

Both work without an index: the weight model ships with the package. `rescore`
and `discover` rebuild a dataset and live on the operator plane, not the public
CLI. See [Self-hosting](/docs/self-hosting).

## Setup and credentials

```bash
# interactive: store the key, then wire up every assistant found (MCP + skills)
lurq setup

# scriptable: no prompts, no browser
lurq setup --yes --no-open --api-key <key> --agent all

# just one assistant
lurq setup --agent claude-code

# point at your own serve-http instead of api.lurq.run
lurq setup --url https://lurq.internal/mcp

# forget the stored key on this machine
lurq logout
```

The endpoint is stored with the key, so a later bare `lurq setup` stays on your
server. `LURQ_ENDPOINT` overrides it for a single command without changing what
is stored.

`lurq install` and `lurq login` are aliases for `lurq setup`.

`install-skill` is the older, narrower command: it writes MCP entries and skill
files but does **not** store the key for the CLI. Prefer `setup`.

```bash
# self-host: wire your agent to a local stdio server instead of the hosted API
lurq install-skill --local
```

## Output format

Every command supports `--json`:

```bash
lurq recommend "state management for react" --json
```

This emits structured output suitable for piping into other tools, the same
shape the MCP layer serializes.
